# Strongbox: independent correctness review

Reviewed base: `2e35159be7fea478a68f103c9dfc05adeaed18bf`, `paulmalmquist/storage_relspace`.
Review branch: `review/strongbox-2e35159`. Review began November 7, 2026, America/New_York.

**The eight guarantees do not all hold. Six High findings are fixed on this branch; twelve Medium findings remain open, with executable failing tests.** The original integration suite passed before these tests were added. Passing that suite was not evidence that the stated guarantees held.

Findings below come from code execution against PostgreSQL 16 using the restricted runtime login, or from cryptographic/schema checks. Documentation was checked against that behavior. All data was synthetic. No cloud project or deployment was accessed.

Locations in the issue tables refer to the **reviewed base commit**, so they remain useful when comparing the fixes. Likelihood describes the triggering circumstances, not an estimated probability of exploitation. An SQL reproduction demonstrates the service-bug containment boundary; it does not imply apps have database credentials.

## Reproduction and commit evidence

```bash
export STRONGBOX_TEST_DATABASE_URL='postgres://postgres:password@localhost:5432/strongbox_test?sslmode=disable'
export STRONGBOX_REQUIRE_INTEGRATION=1
go test -race ./...
```

The High tests are ordinary tests beside the affected packages. To run just those and the new catalog safeguard:

```bash
go test -race ./internal/service ./internal/backup ./internal/store -run '^TestReview' -v
```

To reproduce the open Medium findings, run this **expected-failing** command:

```bash
go test -race -tags strongbox_review_repro \
  ./internal/service ./internal/store ./internal/api ./internal/backup \
  -run '^TestReview' -v
```

## Correct today, fragile without safeguards

- **Schema reasoning:** add implication tests that compile both schemas and search for old-valid/new-invalid witnesses. Unknown validation keywords and draft changes should force migration unless their interaction is proved. Keep explicit `const: null` and patternProperties witnesses.
- **Migration coordination:** add cancellation/switch tests with two workers paused between collection reads, migration-row locking and batch commit. The batch does not take the same advisory lock as request writers. Test a late failing batch after defaults already rewrote earlier records; state exactly which changes are resumable versus atomic.
- **Retention and receipts:** retain referenced revisions through receipt expiry, or make expiration a distinct response. Make the invariant executable rather than relying on independently chosen history and receipt lifetimes.
- **Upload parts and cleanup:** test two simultaneous first writes of the same part number, plus unknown outcomes and revocation between external write and row commit. Add accounting/reconciliation for unreferenced attempt objects. Unique object names and leases are useful, but do not by themselves prove absence of orphan ciphertext.
- **Catalog invariants:** keep `TestReviewAllAppTablesForceRLSAndDefinersPinPath` in CI. Expand it to approved role memberships, immutable-column grants and scoped queue/object constraints. New SECURITY DEFINER functions should require explicit review.
- **Growing scans and fairness:** allowedMarkings scans the app/scope's retained marking catalog, which never shrinks. History caps pages at 200, but collections/teams/members and some worker enumeration are unpaged; export holds its SQL snapshot while copying objects. Verify pages records/revisions/blobs, but holds a transaction while decrypting a page, including deep blob I/O. Add fixed-size/byte budgets, resumable operator cursors, slow-KMS tests and a worker fairness test with one sustained backlog.
- **Recovery input:** cap restore batches by bytes as well as 500 rows; the 64 MiB per-line ceiling does not bound a whole batch. Validate column consistency for every row, not only the first row's column list. Add symlink confinement and concurrent source-delete/export tests before treating filesystem bundles as independently trusted archives.
- **Deployed retention:** Terraform enables versioning, seven-day soft delete and age-based noncurrent expiration. The logging bucket defaults to unlocked. Treat those as configuration intent until a deployment-specific check confirms IAM, sink delivery, retention and lifecycle execution. No cloud validation was performed here.

These are safeguards and test gaps, not additional ranked vulnerabilities claimed without reproduction.

## Inaccurate or overstated documentation

Architecture and operations wording was corrected on this branch where possible. Remaining code gaps are explicitly identified, not represented as fixed by documentation.

| Statement at the reviewed base | Correct wording |
|---|---|
| `ARCHITECTURE.md`: Run is the only database path. | App resource transactions use Run. Principal registry reads/listing/provisioning helpers still use the pool directly; authentication therefore lacks its acquisition budget. |
| Disclosure rules: no count endpoints or plaintext search indexes. | `/usage` exposes app-wide counts/bytes, migration status can disclose private IDs, and unencrypted UNCONTROLLED collections have plain equality tokens. Encrypted collection indexes use HMAC tokens. |
| Revocation applies to the next statement any request runs. | New requests re-read identity and access policy. Already-authorized streams may complete. Upload status still lacks the classification recheck in M06. |
| Every mutation has an operation ID and every retry returns its original result. | IDs are optional at the API, several mutations ignore them, first-use key races break fingerprints, and pruned history currently makes record replay return another version. |
| The compatibility checker proves every accepted change widens the schema. | It recognizes a useful subset but has reproduced unsound cases involving null const and patternProperties. |
| Failure table promises 503 for unknown commits and original retry results. | Unknown commits now preserve referenced ciphertext and return 503 on this branch. The original-result promise remains limited by M04. |
| `OPERATIONS.md`: an export is ciphertext readable only with KMS, and every encryption context contains app. | SQL rows are serialized as stored; plaintext UNCONTROLLED data/tokens and metadata remain readable. Current ciphertext contexts bind app; legacy contexts intentionally retain older formats. |
| Principals absent from the target are simply added during restore. | After H06, populated targets require prior target-side provisioning and preserve existing policy. Only an empty target imports the source registry. |
| The audit sink writes to a locked bucket. | Terraform initially creates an unlocked bucket. The operator must configure and lock retention before claiming an immutable independent copy. |

The requested “different database” guarantee is stricter than the operations document's existing “database and schema” wording; M12 is an implementation/requirement gap, not a misquotation of that document.

## Validation record

See `docs/evidence/review/validation-summary.json`, the per-High red/green logs, `open-reproductions.log`, `typescript-live.log`, and `load-smoke.json`.

- Go 1.26.10, PostgreSQL 16.15, Node 22.18.0.
- Original full integration suite: passed with `STRONGBOX_REQUIRE_INTEGRATION=1` and `-race`.
- Final full suite: **149 tests passed**, no skipped tests, with integration required, race detection, `-count=1` and `GODEBUG=fips140=only`. The separate frozen-module suite also passed with `GOFIPS140=v1.0.0 GODEBUG=fips140=only`.
- Frozen `GOFIPS140=v1.0.0` build and enforced `fips-check`: passed.
- TypeScript generation check, typecheck, build, nine live/unit tests and the example: passed.
- Go vet, Staticcheck 0.8.2 and govulncheck 1.9.0: passed. The vulnerability scan reported no reachable vulnerable symbols; it noted one advisory in a required module with no demonstrated call path, which is not reported here as a reproduced issue.
- Synthetic load smoke: eight virtual users, two-second workloads, 25/100 requests-per-second arrival steps. Private-state versions, shared counter totals, 225 blob readbacks and create counts matched the harness's independent final-state checks. These are local smoke results, not production capacity or fairness SLAs.

The environment required a local uid-check shim to start the stock PostgreSQL binary because changing OS users was unavailable. SQL roles, RLS, PostgreSQL data handling and application cryptography were not patched. Docker image execution and live Terraform/IAM/KMS/bucket validation were not performed. The repository changes do not deploy infrastructure or change main.
